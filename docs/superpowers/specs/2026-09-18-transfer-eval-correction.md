# 单篇风格迁移评测修正（2026-09-18）

状态：已完成实现、45项评分与4个机制控制，结果见 ../../2026-09-18-transfer-eval-results.md。仅调整评测、补充验证和结论，不修改提取提示词、现有Spec、生产生成包装、.env或默认学习方法。

## 问题与目标
旧迁移评分将源文内容污染和新增事实混为cleanliness，再与任务遵循平均，同一问题可能重复影响总分。所有风格仅测一个严格素材任务；字数由Judge估算，合理细化边界含糊。因此旧结果只能解释为该测试条件下的综合分，不能作为新提示词整体失败的证据。

## 新契约（Transfer v2）
五个独立维度分别报告，不再合成一个采用总分：风格保真、原文独立性、事实合规、自然度、主题/核心素材完成度。后者不重复扣事实与长度；事实违规只记事实合规，源文内容迁移只记原文独立性。若同一段同时违反两项，须给出两项各自证据；不额外合成惩罚。
- 风格保真只看表达机制，不因新事实扣风格分，也不因风格特征多而忽略机械堆砌。
- 原文独立性区分写法与内容：人称、节奏、短功能词不算污染；携带具体人物/物件/事件/观点答案或固定内容关系才扣分，必须同时引用正文与样文可定位片段。
- 事实合规按任务模式评。严格模式允许同义转述、逻辑解释和不增加独立事实的连接动作；新增人物履历、时间数值、物件、对话主张、独立事件等须有素材支持。不能一边把新增物件当合理细化，另一边把同类内容当虚构。难判的轻微动作记uncertainties，不臆测扣分。
- 场景创作模式允许虚构人物、动作、对话和事件且须明确虚构/假设；不因这些创作扣事实分，但仍检查与给定核心事实冲突、冒充现实经历、伪造外部真实统计/引用。
- 字数由程序按非空白Unicode字符（含标题/标点/Markdown）统一统计，600–900含边界，单独报告达标率/超短超长，不让Judge估算或在其他维度重复扣分。历史任务字数口径未明，新计数只用于统一诊断，不倒推历史口径。
- 评分范围/类型、证据摘录存在性和低分对应证据由程序校验；最多一次诊断修复，原始响应和修复各自留证。

## 实验设计
1. 历史重评：复用此前同模型生成的旧单阶段、两阶段修正版、自由格式单阶段的15篇图书馆文章，不重生成、不重新提取、不向Judge提供方法名称/Spec/旧分数；去掉样文元信息标题，仅保留源正文。比较同一篇文章在新旧维度下的诊断，禁止跨不同量尺做总分差。
2. 补测：五份样文的三个已冻结Spec，各生成两个任务模式，共30篇新文。使用同一“社区旧物修理日”完整素材包，仅变化事实/创作权限；固定同一个生产大纲/正文包装，所有方法一致。新文章明确600–900非空白字符。每篇一次采样，三方法轮换调用顺序，每次最多3并发。
3. Judge机制自检：固定四个短控制样本，检查新增事实在严格/创作模式下的差异、源文内容搬运是否跨模式都识别、长度不影响语义评分。控制失败照实记录，不为迎合胜负改裁判或隐去结果。控制短文仅检查评分隔离，不纳入方法质量均分。
4. 报告按历史重评/严格补测/创作补测分别列五维和字数达标率、逐样文配对差异、胜平负与证据；检查点逐请求保存，冻结输入包括规则、完整Spec/文章、模型、模板、方法映射。错误不记为成功；同run_id断点续跑。
5. 预先约定：本轮不自动切换默认，也不以任意加权总分宣布胜者；如方法在各任务/维度表现不同，报告其适用条件。必须保留同模型Judge、一次采样、仅两题材/一新题材、开发集的局限。多文章学习仍不在范围内。
