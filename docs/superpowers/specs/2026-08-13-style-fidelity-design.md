# 写作风格遵循度改进设计（v2 · 已落地）

## 状态

已实现（2026-08-13）。本方案取代上一版"仅评审"设计，直接落地代码、风格文件与提示词。

## 诉求

生成的正文没有稳定体现出用户提供的风格；风格提示词本身废话太多（分析报告、原文示例、解析混在执行指令里）。

## 根因（已核对代码，非推测）

1. **提取提示词产出错误形态**：`prompts/learn_style.md` 要求输出"10 维度分析报告 + 原文示例 + 解析 + 复刻指令"，`src/learn.rs` 把整份产物写入 `styles/{name}.md`，再整份注入正文 system prompt。模型得自己区分哪些是背景、哪些是硬约束。
2. **风格文件规则冲突**：`styles/qingbian.md` 末尾被追加了与 `wechat_base.md` 相同的通用排版/语气/去 AI 味模板，与正文的逆向分析冲突——"频繁用你代入" vs "以我为主视角"、"频繁设问" vs "全文反问 ≤1 句"。这些冲突来自通用模板，不是轻辩本身。
3. **大纲阶段无风格**：`src/generate.rs` 与 `src/repl.rs` 各有 `OUTLINE_SYSTEM_PROMPT` 副本，均不含风格，大纲生成不接收风格，风格无法影响破题、结构、论证顺序与结尾。
4. **无生成后风格验收**。

## 设计决策

**核心：风格文件 = 精简执行指令（Style Spec），不是分析报告。**

- 提取提示词直接输出 10 段固定结构的执行 spec，不再产出原文示例/解析/叙述性分析。
- 同一份 spec 同时注入**大纲**与**正文**两个阶段。
- 正文阶段在风格外包一层"通用约束 + 事实边界 + 只输出正文"的系统提示词，把每个风格文件里重复的通用规则剥离到代码里，避免漂移。

## Style Spec 结构（唯一分类主轴）

10 段，覆盖四层判断标准：

| 层 | 对应段 |
|---|---|
| 结构层 | 标题 / 开头 / 结构与论证 / 结尾 |
| 论证层 | 结构与论证 |
| 表达层 | 段落与句式 / 语气与人称 / 用词 |
| 排版层 | 排版 |

```
## 定位
## 标题
## 开头
## 结构与论证
## 段落与句式
## 语气与人称
## 用词
## 结尾
## 排版
## 禁止
```

约束：全文 ≤600 字；每条可执行；无原文示例；冲突时「禁止」优先（由正文系统提示词兜底）。

## 代码改动

| 文件 | 改动 |
|---|---|
| `src/generate.rs` | 新增 `outline_system_prompt(style)` / `style_system_prompt(style)` / `render_prompt(outline, idea)` 三个 prompt builder；`generate_outline` 增加 `style` 参数；`render_fulltext` 用 wrapper + 共享 render_prompt；CLI 双通道 `generate_with_outline` 同步注入风格并去重 |
| `src/repl.rs` | `handle_generate` 把 `style_content` 传入 `generate_outline` |
| `src/learn.rs` | 无逻辑改动（提取提示词已改为直接输出 spec，写盘路径不变） |

## 非目标

- 不引入生成后审查/重写闭环（额外 LLM 调用，留待需要质量门禁时再加）。
- 不引入 JSON Schema / 数据库 / 结构化持久化。
- 不改 LLM provider、模型、主题与素材提取逻辑。
- 不改 `refine.rs` / `update.rs`（局部重绘/整文重写是独立流程，不依赖风格文件）。
- 不改风格名模糊匹配逻辑（`轻辩`→`qingbian` 的匹配是独立于本方案的既有问题）。

## 验收

### 功能
- 大纲调用与正文调用都能收到风格 spec。
- 正文只收到精简执行指令，不收到抓取说明/分析报告/原文示例。
- 风格文件不再有互相冲突的硬约束。
- 正文系统提示词明确禁止素材外事实与写作过程输出。

### 质量
- 同一主题生成 3 篇，人工逐项检查 7 项（破题/论证动作/段落节奏/句式人称/语气词汇/结尾/AI 套话与事实幻觉），≥5 项稳定符合，且无素材外精确事实。

### 工程
- `cargo test --lib` 全绿；`cargo build` 无警告。
- prompt builder 有单元测试覆盖"风格确实注入大纲与正文"。
- 不使用 `allow(dead_code)` 或静默吞错。
