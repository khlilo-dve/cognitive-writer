# 抖音脚本：我把一个命令行工具重构成了 AI Agent

> 时长：约 6-8 分钟 | 风格：坐镜头前直接说，偶尔切屏幕录制

---

## 开场（30 秒）— 这是什么，变了吗

（屏幕录制：终端里敲 `cargo run`，出现 REPL 提示符，打一行自然语言，Agent 自动生成文章）

> 这个项目叫 cognitive-writer。之前它是一个命令行工具——你得记住子命令、参数名、文件路径，像操作一个高级点的脚本。
>
> 现在我把它改成了一个 Agent。你对着终端说话就行。"写一篇关于认知偏差的文章，轻辩风格"——它自己会去匹配风格、生成大纲、渲染全文、注入剪贴板、把 MDX 写到个人网站目录、等你确认后 git push 上线。
>
> 听起来好像很厉害，但其实整个重构过程我犯了一堆错。今天就是想分享一下这个过程，以及我理解的 Agent 到底是什么。

---

## 第一段（1 分钟）— 我理解的 Agent，可能不对

> 先说 Agent。这个词今年被用烂了，好像什么东西套个 LLM 都能叫 Agent。我自己理解下来，其实就三个东西：
>
> **感知**——它能听懂你在说什么，不用你学它的语言。
> **推理**——它能根据当前情况决定下一步做什么。
> **行动**——它不只输出文字，它真的会去改文件、调 API、推代码。
>
> 大部分 Chatbot 只有前两个。能聊，但不动手。Agent 多了一个"动手"。
>
> 我做的这个东西其实就是个垂直 Agent——它不会写代码、不会查天气、不会订机票。它只做一件事：把你说的话题变成两边都上线的文章。但这条链它做到端到端。
>
> 我一开始其实没想清楚这个。我以为 Agent 就是多加几个 if-else。

---

## 第二段（1.5 分钟）— 第一次重构的坑：关键词匹配

> 最开始我想得特别简单。用户输入嘛，找关键词就行了。"写一篇"+"用"+"风格"→ 生成文章。有 URL → 学习风格。"OK"→ 确认。
>
> 然后我就上线了。然后我就傻了。
>
> 我自己试用的时候说了句"帮我整一篇关于认知偏差的，要那种犀利点的感觉"。结果它回我——"没理解你的意思"。
>
> 因为它找不到"写一篇"这三个字，也找不到"风格"这两个字。我就想，我一个创造者自己被自己的工具拒了。就很挫败。
>
> 后来才反应过来——我在用一个规则引擎去理解自然语言，这根本就是方向性错误。Agent 的核心是 LLM 理解，不是关键词匹配。
>
> 所以后来补了一个 LLM 分类层。每次用户输入先进 LLM，用一个小 prompt 分类成结构化意图。"帮我整一篇认知偏差的，犀利点"→ 正确识别成 Generate。关键词匹配降级成 LLM 挂了的时候的保底。
>
> 这个教训说白了就是：不要试图用规则穷举自然语言。你写不完的。

---

## 第三段（1.5 分钟）— 第二个坑：状态机

> 关键词的问题修完以后，又来了一个新问题。用户和 Agent 的对话是有上下文的。
>
> 比如用户说"OK"——在刚开始的时候"OK"没有意义，但在确认大纲的时候"OK"就是继续。同样，"第三段加个案例"——只有在已经有全文的时候才有意义。
>
> 我用了一个四状态的状态机：Idle → WaitingForFulltext → WaitingForPublish。每个状态下只接受对应的指令。不在这个状态的输入会被拒绝。
>
> 这里其实有个过度设计。我一开始设计了三个检查点——大纲确认、全文确认、发布确认。后来发现大纲确认是多余的。LLM 生成大纲的质量已经很稳定了，再让用户确认一个中间产物就是多余的操作。所以后来砍掉了大纲确认，大纲→全文一气呵成。
>
> 这个教训是：能砍的步骤就砍。不是你设计了多少，是用户少按了多少次回车。

---

## 第四段（1 分钟）— 第三个坑：进程死了数据全没

> 还有一个问题，也是我觉得很多人做终端工具会遇到的。你在 REPL 里写了一篇文章，确认了大纲，到了全文确认阶段——终端关了，或者进程崩了。什么都没了。
>
> 这个感觉特别差。你花了半小时，AI 帮你生成了内容，就因为进程死了，全部归零。
>
> 我的修复特别简单。每次操作后把整个 Repl 结构体序列化成 JSON，写到 `~/.cognitive-writer/current.json`。启动的时候检查这个文件，有就提示恢复。
>
> 没有数据库、没有 Redis、没有 HTTP API。就一个 JSON 文件。但你随时可以 Ctrl+C，下次回来接着干。
>
> 有一种东西叫长连接——多会话、WebSocket、状态同步。但我的场景用不上那些。我只需要：进程死了，状态还在。

---

## 第五段（1.5 分钟）— 架构变化和数字

> 说点实在的。整个项目的代码量变化：
>
> v2.1 的时候 main.rs 是 667 行一个上帝函数。现在 main.rs 126 行，整个项目拆成了 14 个源文件，132 个单元测试。
>
> 增加的模块包括：意图解析器、REPL 循环+状态机、网站发布模块、风格库管理。异步事件循环和会话持久化是 v3.1 刚加上的。
>
> 技术栈一直是 Rust。LLM 用的是 DeepSeek，OpenAI 兼容协议。网站那边是 Next.js + Vercel 自动部署。公众号因为我是个人订阅号，没有 API 权限，所以保持剪贴板注入——后台 Ctrl+V 就行。
>
> 最大的变化不是技术，是交互模型。从"你学我的命令"变成了"我学你的语言"。

---

## 结尾（30 秒）

> 这个项目说实话 bug 还挺多的。run_learn 和 run_update 里面还有 process::exit，在 REPL 里会直接杀进程。很多函数有一模一样的副本散落在不同文件里。clap 依赖已经没用了但还没删。
>
> 但我自己的感受是——一个东西不需要完美才能拿出来。它只要能解决你的问题，剩下的慢慢迭代就行。
>
> 如果你也在做类似的东西，或者对 Agent 的实现细节感兴趣，代码在 GitHub 上开源的。搜 cognitive-writer 就行。
>
> 就这样，拜。
