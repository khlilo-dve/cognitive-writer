# 正文风格学习核心 v1

当前目标是先提供可复用的正文学习能力，输入获取在后续阶段实现。核心接受1–10篇正文，单篇与多篇走同一条链：完整原文→Pro长篇声音分析→Pro内容隔离编译→执行Markdown。模型调用通过注入接口提供，核心不读取`.env`、不抓网页、不写正式风格库。输出始终标记为待审草稿，内部分析和来源身份与Writer说明分开。

算法先按非空白正文哈希排成规范顺序，同一文章集合在输入换序时构造相同模型上下文；重复、空文及超10篇在发送请求前报错，不静默截断或用重复文章增加权重。每篇保存原始文本哈希与规范化身份，方法和两份提示词哈希进入产物指纹。增加文章时对最多10篇全量重新综合，暂不把旧Style当作证据递归压缩，避免错误逐轮放大；版本保存与用户预览以后由外层负责。

两阶段均使用Pro，是因为实测Flash剥离源文案例失败。执行说明只保留声音关系、写法动作、适用条件、变体与误用；原文故事、引句和长篇分析不注入Writer。程序拒绝空/损坏执行文本和明显原文长片段复制，最多一次诊断修复；样本范围与潜在机械配额另记警示，不能靠规则条数或文件长度证明质量。词级或语义内容泄漏及无依据概括仍需审阅，核心不会标记自动采用。

研究侧用两作者的1/3/10篇验证无人工内容词表的实际链路，明确报告模型失败、语义问题与费用。先前两题八稿都完成，但地图稿普遍补出未给的场景，按钮稿也有无依据的存储推断；这说明Writer事实遵守尚未通过，不能用它们宣布系统可靠。本文对应核心API实现和开发验证，不宣称正式CLI/REPL多篇功能已交付。

## 已完成的验证与调用边界

`voice-learning-core-01`两作者各1/3/10篇六组均完成，13份请求检查点复跑全部缓存命中、0新请求、账本不变；运行`python3 scripts/verify_voice_core.py`核对阅读副本、来源、规范顺序和复跑证据。输入换序/重复/超限/有界复制修复的库测试已通过。`VoiceDraft.fingerprint`只标识输入集合、方法和提示词，具体模型、端点指纹及usage由注入调用方保存；研究适配器使用既有ResearchStore完成这层留证。

公开入口为`voice_learning::learn_voice_with(articles, prompts, call)`；call接收阶段名、system与user并返回`Result<String, AppError>`。`VoicePrompts::load()`加载两份核心提示词；调用者也可显式构造提示词。输出的`analysis`只供审阅，只有`spec`可交给Writer，`status`始终为`draft_pending_semantic_review`。已知语义问题及下一步见研究run的`semantic-review.json`；保存/版本/输入追问交给后续外层，不在核心中读取stdin或隐式覆盖文件。
