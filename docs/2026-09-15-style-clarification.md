# 首次文章生成的风格追问（2026-09-15）

用户审核方案后授权执行，范围为 REPL 空闲态发起文章生成时补齐风格选择。

## 行为
- 未指定风格、未知风格、多个名称匹配、描述性匹配均进入追问，不直接报缺参错误或自动取首个结果。
- 明确名称及中文/拼音唯一匹配直接生成；“最近用过”等无法落实为具体名称的输入继续追问。风格库只有一项时也需要明确选择。
- 候选按实际文件名显示编号和摘要。支持名称、编号、“用某某风格”，确认词不能代替选择；/styles 和“有哪些风格”等查询保持原请求。
- 空库提示学习/导入，读取和模型故障保留实际错误。新增条目后可 /styles 刷新；已显示的编号按会话中的名称列表解释，避免重启后目录重排误选。
- 选择明确后直接进入原有大纲与正文流程。原始请求与主题同时传入两阶段调用，保留字数、受众、语气等要求，风格以当前选择为准。
- 等待选择时 /quit、Ctrl+C、EOF 保存；重新启动恢复后继续选择。/cancel 或自然语言取消清除待生成需求。

## 实现
- intent_classify.rs：允许 Generate 缺少 style_name；提示词要求仅提取用户原话中的明确风格；响应里的名称在原输入中找不到时回退追问。
- style_selection.rs：目录读取、准确名称匹配、完整候选收集与短句选择解析；读取错误和空目录分别处理。
- repl.rs：WaitingForGenerationStyle 状态、原始需求与候选顺序持久化、明确选择后的生成调度；旧会话新增字段使用 serde default。

本次验证覆盖交互和数据传递，不作为真实模型识别准确率评测。CLI 和正文阶段换风格保留原流程。
