# 草稿保存与会话恢复修复（2026-09-15）

## 行为
- 确认正文时，只有本地 Markdown、HTML 和已配置的网站 MDX 均写入成功，才进入发布等待态。
- 任一写入失败会保留正文和确认状态，提示修复目录后确认重试，或保存会话退出；不会提示“草稿已就绪”。已成功写出的文件保留，重试创建下一归档版本。
- 三类草稿采用已有的原子文件写入机制，失败不留下半截目标文件、不截断旧网站草稿。剪贴板失败单独提示可从本地 HTML 复制；暂缓提示不再声称剪贴板注入或网站写入必然发生。
- 恢复接口改为 Result<Option<Repl>, AppError>：仅文件不存在返回 None；读取、解析、配置失败都报错并停止启动，原文件不改动。正常旧会话继续兼容。

## 验证
- cargo test --lib：181 通过，7 个真实模型入口按原规则忽略。
- cargo build --bin cognitive-writer：通过。
- python3 scripts/verify_repl_terminal.py：17 项通过；保留原 11 项，新增损坏 JSON、无效 UTF-8、不可读取会话路径，以及本地目录、HTML 写入、网站草稿三类失败。
- 草稿故障使用隔离目录与文件大小限制；验证仍在正文确认态、正文可保存并再次启动恢复、失败 HTML 和 pending 文件不残留。
- 单元测试额外覆盖目录修复后重试成功、网站写入失败时保留本地副本、旧会话恢复和缺少配置时原文件不变。

## 边界
损坏会话不会自动猜测修复：按提示修复原文件，或移走备份后重新启动。发布超时、默认风格选择、局部修改范围和风格格式校验仍属后续工作。
