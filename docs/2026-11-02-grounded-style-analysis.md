# 风格分析的来源关卡与有界修复

2026-11-02，承接方法29的限定语修正。生产默认learn/REPL、styles和.env不变；改动作用于正文学习开发核心。

## 要解决的实际问题

原链中存在三类不同问题：分析的限定在编译中被强化；Writer执行文件混入源文故事；更早的分析竟引用了不属于请求原文的材料。请求/响应哈希只能确认文件对应，不能确认模型引用真实。原文直入编译、隔离恢复和首次引文关卡分支均保留原响应、费用和失败结论，不能只把后续成功稿留下。

## 当前合同

voice-core-v6的analysis与analysis-repair阶段使用原生JSON，analysis字段仍是详尽自然Markdown，evidence字段是article/quote数组。程序逐条核对来源ID、非空连续原文摘引，以及每篇至少有一处依据。它只验证引用归属，不宣称概括语义全部正确。原始JSON由调用方逐阶段保存；VoiceDraft.analysis保留分析正文，编译器只接正文与篇数，不接完整原文或证据数组。Writer仍只收到自由格式执行Markdown。

分析无效时最多一次修复，输入包含原任务、无效分析、具体错误及程序从对应原文中定位的候选片段。候选片段只供定位；程序不会把近似引用自动算作逐字引用。修复后仍不满足合同则直接失败，后续编译与保存不会发生。传输未知请求仍不自动重试，旧费用预留保留。

分析正文使用中文引号，证据选必要连续短句，避免长JSON字符串中的未转义引号与重复复制；没有对Writer风格文件设字数、标题或手法次数配额。

## 验证

新增三项真实错误边界测试：错文引用经过一次修复仍无效时不进入编译；有效修复后正常编译且证据不会进入编译输入；定位候选片段不能放宽逐字核验。既有十篇来源、版本恢复和原文隔离测试同步使用新分析合同。282库测试通过、10在线入口默认忽略。17项既有终端回归通过；本地HTTP17请求覆盖上述新建/追加/冻结恢复、错误证据修复、持续错误阻断、缓存拒绝与Ctrl-C。
