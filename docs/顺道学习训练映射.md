# 顺道学习训练映射：cognitive-writer 优化 × AI 产品人系统学习方案

> 目的：把「优化 cognitive-writer 过程中正好能顺道练到的训练点」一一列出来，避免为了学习而单独学习。
> 依据：《AI 产品人系统学习方案》（Track A 构建能力 + Track B 判断决策 + 心法篇）。
> 原则：**所有练习挂在 cognitive-writer 这个具体产品上，不另起学习项目。**
>
> ⚠️ **关键区分：AI 做完 ≠ 你练完。** 表里的「AI 已产出」指 AI 在这次优化里完成了对应动作（重写 prompt、跑 eval 等），但**这不等于你训练了**。学习方案的「练」要求你**亲自做**——尤其心法五「用自己的话复述」、心法八「产出才算数」（有数字、有可运行的东西）。AI 产出只是搭了个「能练」的场子，真正的练还欠着。别把 AI 的产出当成自己的训练记录。

---

## 总览：这次优化里 AI 做了哪些（哪些还欠你亲自练）

| 学习方案训练点 | 本次优化的对应动作 | 状态 |
|---|---|---|
| A1 Day 1（system vs user message） | 把生成 prompt 拆成 system（风格硬约束）/ user（大纲+素材） | AI 已产出｜待你亲自练 |
| A1 Day 4（Prompt 模板化） | 三个 prompt builder + `{style}`/`{outline}`/`{idea}` 占位符，改 prompt 不碰代码 | AI 已产出｜待你亲自练 |
| A1 Day 6（递归迭代 prompt） | 风格提取/生成提示词重设计 → 真实 LLM 跑 eval → 看输出对比 | AI 已产出｜待你亲自练 |
| A4 Day 17-18（给 cognitive-writer 建 eval） | 两条真实 LLM 评测（提取 spec、风格化生成） | AI 已产出（评测跑过未固化）｜待你亲自固化 |

**结论**：AI 已经做完了 A1 前半段（Day 1/4/6）的产出动作（prompt 重写、eval 跑了），但**这不是你练了**——你还没亲自复述、没亲自改 prompt、没亲自跑 eval。真正的练要你把这些动作自己做一遍。剩下的大头是 **A4 Eval 系统化** 和 **A3 Agent Loop**，这两个正好对应后面的大方向，也是你接下来亲自练的主场。

## Track A：AI 构建能力

### A1 — Prompt Engineering（Week 1-2）

| 训练点 | 在优化中怎么顺道练 | 状态 |
|---|---|---|
| **Day 1**：system prompt = 持久规则，user = 单次任务 | `src/generate.rs` 的三个 builder：`outline_system_prompt`（持久规则）、`style_system_prompt`（硬约束包装）、`render_prompt`（单次任务：大纲+素材）就是活教材。可练：标注每段 prompt 属于「角色/任务/格式约束」哪一类 | AI 已产出｜待你亲自复述 |
| **Day 2**：JSON Schema 约束输出 | 意图分类器 `classify_intent` 已经是「输出 JSON」约束。进阶：把风格文件从 Markdown spec 演进成 **JSON Schema Style Profile**（方案 C），直接练结构化输出 | ⏳ 待做（对应大方向） |
| **Day 3**：Few-shot vs CoT | `INTENT_CLASSIFY_PROMPT` 目前靠文字描述，可加 2-3 个 few-shot 示例（如「整一篇/来一篇 = Generate」），实测 few-shot 对分类准确率的提升 | ⏳ 待做（低成本） |
| **Day 4**：Prompt 模板化 | 已把 prompt 抽成 builder + 占位符，改 prompt 不碰代码（本 session 实锤：重写 `prompts/learn_style.md` 和 `styles/*.md` 全程没动代码） | AI 已产出｜待你亲自练 |
| **Day 5**：上下文窗口管理 | 素材直接整段注入 `render_prompt`，长素材无策略。可练：全文 / 手动摘要 / LLM 摘要三种喂法对比 | ⏳ 待做 |
| **Day 6**：递归迭代 prompt 闭环 | 本 session 就是一轮完整「诊断→改进→跑 eval→对比」。可固化成 Day 15 的标准流程 | AI 已产出｜待你亲自重做+固化 |

### A2 — Harness 基础（Day 9-10）

| 训练点 | 在优化中怎么顺道练 | 状态 |
|---|---|---|
| **Day 9**：SessionStart Hook + Skills | 给 cognitive-writer 配项目级 SessionStart hook（自动加载 CLAUDE.md + 检查 .env），写 `/prompt-debug` skill | ⏳ 待做 |
| **Day 10**：Settings 治理 + Memory | 审计项目 `.claude/settings.json` 白名单，清理过时 memory | ⏳ 待做 |

### A3 — Agent 最小感知（Day 11-12）

| 训练点 | 在优化中怎么顺道练 | 状态 |
|---|---|---|
| **Day 11**：Agent Loop 感知 | 「生成→审查→重写」闭环（方案 D）就是固定流程变 Agent Loop 的最小例子——观察 LLM 什么时候该停、什么时候该重写 | ⏳ 待做（对应大方向） |
| **Day 12**：最小 Agent Demo | 把「审查+重写」写成 <70 行的最小循环，感受工具描述 > 工具实现 | ⏳ 待做 |

### A4 — Eval 与质量验证（Day 13-18）★ 最重要

| 训练点 | 在优化中怎么顺道练 | 状态 |
|---|---|---|
| **Day 13-14**：建 eval 脚本 | 把本 session 的两条评测（提取 spec、风格化生成）固化成可重复脚本，算风格盲评准确率、质量清单通过率 | ⏳ 待做（对应大方向） |
| **Day 15**：标准 prompt 迭代流程 | 固化「跑 eval → 改一处 → 跑 eval → 看数字 → 保留/回滚」 | ⏳ 待做 |
| **Day 16**：LLM-as-Judge | 方案 D 的审查模型就是一个 judge——练「用 AI 检查 AI」 | ⏳ 待做（对应大方向） |
| **Day 17-18**：给 cognitive-writer 建 eval | 3 种风格 × 同主题生成 → Claude 盲评风格分类 → 记录准确率；建质量清单，检查历史输出通过率 | ⏳ 待做（对应大方向） |

## Track B：判断与决策能力

| 训练点 | 在优化中怎么顺道练 | 状态 |
|---|---|---|
| **B1 机会成本** | 「要不要上方案 D（审查重写闭环）」的决策：做 D 的成本 = 放弃的别的优化（如 eval 基线）的价值。用机会成本框架写决策记录 | ⏳ 待做 |
| **B2 沉没成本** | 技术债清理（`process::exit`、`clap` 依赖、死代码）：已花的时间 ≠ 继续留着的理由 | ⏳ 待做（这次清理正好用） |
| **B4 叙事写作**（贯穿，每天 30min） | cognitive-writer 本身是写作产品——每周公众号长文就是用产品产出「教别人」的输出，同时检验自己的判断框架 | 🔄 持续 |

## 心法篇：这次优化里 AI 踩中的心法（你还没亲自踩）

| 心法 | 本次体现 |
|---|---|
| **心法三 学练用造** | prompt 重写是「练+用」，风格 spec 化是「造」（完整作品） |
| **心法四 苍蝇→蜜蜂** | prompt 迭代从「先乱试几种写法」到「定型 spec 结构」 |
| **心法五 复述** | 写设计文档、总结文档 = 用自己的话复述，强化「这是我想出来的」 |
| **心法八 践行才算数** | 评测用真实 LLM 跑出数字（456 字 spec、风格贴合输出），不是「我觉得变好了」 |

---

## 建议的「顺道学习」节奏

1. **立刻能做的**（≤1 小时/个）：A1 Day 3 few-shot 标注、B2 沉没成本框架写进技术债清理记录。
2. **下一步重点**（= 大方向里挑）：A4 给 cognitive-writer 建完整 eval（Day 13-18 一口气顺下来），这是学习方案里唯一明确点名「给 cognitive-writer 建 eval」的训练，也是当前产品最缺的。
3. **跟着大方向走**：A3 Agent Loop 感知 → 做方案 D 时自然触发。

> 一句话总结：**这次优化是 AI 做的，不是你的训练。A1 前半段（Day 1/4/6）AI 已经走了一遍，但你需要亲自复述、亲自改 prompt、亲自跑 eval 才算练。剩下的学习重点不是「新学概念」，而是「把 A4 eval 从随手跑变成标准流程」——由你亲手做，正好落在 cognitive-writer 下一步最该做的工程上。**
