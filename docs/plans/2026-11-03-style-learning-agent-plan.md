# 风格学习子Agent与产品输入链：行动计划

版本：v0.4 · 日期：2026-11-09 · 需求基线：[PRD v0.4](../PRD.md) · 正文核心基线：`b6e4827`，P1/P2基线：`3bf5349`。

当前授权与状态：P0文档已交付；用户随后明确指示按计划开发，P1技术设计与P2采集工具已完成。P3材料领域Agent开发链现已完成，P4主会话开发入口现已完成，P5–P8仍未实施；下方P0执行记录保留当时仅文档的边界，不能当成当前停止开发的指令。验收按阶段证据标记，不把设计走查当运行通过。

## 1. 目标与推进原则

把已可运行的单／多篇正文学习核心接成产品功能：主Agent识别学习意图，风格学习子Agent组织材料、工具、有限追问和学习任务，用户在同一对话中取得候选、保存版本并按需写作。

首先固化产品行为，再做必要技术设计，然后复用现有模块实现。已实现的学习、版本、恢复能力不重新建设；已知语义和Writer事实问题继续留在验收中。局部输入工具开发不必等所有模型输出完美，正式采用与质量结论必须有证据。

每阶段都先更新对应文档条目，再按已授权范围实施；结束后回写真实结果。不重开字数、单多篇胜负或大规模裁判矩阵，不把“换一种提示词再试”作为无限延期的理由。

## 5. 各阶段如何落地与验证

### P2：让输入工具先可靠

先沿现有单篇抓取与正文核心接口找可复用部分。来源清单与文章集合分开，文件／URL数量不是文章数量；提取后的正文、来源定位、失败状态、是否纳入原因一并记录。对正常正文不增加模型访谈。

本地夹具覆盖登录页、目录、多文正文、空文、重复、含命令的正文、中文文件名、混合输入及不可读文件。这里只验证工具语义，不提前用真实API大量学习。改动前先补相应技术设计与PRD细节。

### P3/P4：把Agent自主性与有限交互一起做

用同一任务状态驱动选择：继续取得正文、提交学习、集中澄清、交付、等待或取消。先用可控模型／工具桩验证判断，再做少量真实决策检查。每次工具失败要有原因；同一路径无进展就收束，不能用新任务ID重置循环。

批量读取工具可以一次接收多个来源，避免正常10篇输入被12步的决策预算意外截断。学习工具内部沿用已有阶段和修复上限；不要求每个固定处理动作都再问模型。

主Agent保留整体对话，子Agent不读取stdin。已有“用某风格写文章”路径不误路由学习；组合任务保留写作素材和要求，学习时的澄清回答只消费到对应任务。

### P5/P6：接现有能力，不另建平行系统

复用LearningWorkspace、冻结任务、候选、父版本与旧正文；新增的是材料和Agent交接。先完成两篇可读来源到学习、保存、再读取的竖切，然后补格式与输入异常。新输入改变时必须对应新任务修订，不把旧阶段响应当新输入结果。

保存要求已明确就沿用，不反复确认；没有名称先交候选。追加需核对准确旧版本，合计最多10篇。风格执行文本与原文、内部分析、证据分开，按明确候选／版本交Writer。

### P7：解决已知缺口，有限补验

本阶段拆为独立记录的两项，不合成总分：

- **P7-S 风格学习**：复用身份仍有效的core-v6单篇／双篇产物，核对重要说法与原文限定。若学习方法未变，优先只新增两位作者各一组10篇真实学习，再在少量新题材上看机制与范围；方法变了则只重做受影响的必要项，另起身份留证。
- **P7-W Writer事实**：以已给原始事实核对稿件中的因果、人物／流程、机制和未来断言。先读完已有四稿和具体反例，设计独立核对与最多一次有证据修订；保留原稿、核对、修订和差异，仍无依据就明确未通过，不连抽多篇挑选。

初始新题材检查最多四稿，不开全交叉矩阵。四稿由单／多篇候选分别执行，事实、自然度、风格机制、源文独立分别说明。有限检查不等于统计稳定性或独立盲评；采用说明按证据实际范围写。

P7发现严重语义错误必须修正对应需求／方法或限制可用范围，不能仅补一句“待审”就宣称稳定通过；发现Writer事实问题，不把责任一概推给Style，也不阻塞所有低风险工具建设。

### P8：验证用户真正走得到的链路

覆盖输入→澄清／继续→学习→候选→保存／取消→版本回看→再次使用，以及中断、未知请求、重复恢复、旧候选过期、同名冲突。复跑与测试都在隔离工作区，不能污染正式styles或用户材料。

按项目规则执行cargo test --lib、需要的构建与终端回归、git diff和本地提交。只在本次改动影响相关行为时增加对应检查；不重复大规模试验凑完成数。最终记录产品入口、已支持格式、采用范围、失败限制和恢复方法。

## 7. 预算、失败与止损

基线占用24.556135元，含未知预留6.032614元；既定100元上限尚余75.443865元。若按本计划后续10元上限全部使用，累计不超过34.556135元，余额至少65.443865元。以上是账本预算，不是实付账单或模型套餐价格承诺。

P0–P2新增付费模型API费用0，账本不变。后续开始真实请求前复核实际模型／渠道与usage估算；简单决策优先Flash，困难学习与证据判断Pro，固定工具不调用模型。

传输失败、未知费用、JSON或引用失败都留原回执与判断；最多重试次数沿用明确合同。问题可自主解决就解决，确实无法解决时明确中断对应主任务，说明失败来源、已尝试什么、完成了什么及需要什么才能继续。不能用离线旁支工作代替原定真实验证后宣称完成。

阶段预算用尽或有限修复仍失败，先记录结论和缺口，再按产品范围决定继续其他独立事项或受阻；不为跑出漂亮结果追加分支。
