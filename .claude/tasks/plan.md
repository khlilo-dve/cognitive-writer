## 任务名称
自动工作优先，人工校准最后。

## 影响范围
- 当前执行：eval.rs 的输入修复与评测工具增量补齐、generate.rs 去重、项目文档同步。
- 当前不改变 REPL 状态机和已有公开函数签名；较大改造另列待确认方案。

## 方案
1. 提交已验证的现有修复；纠正文档路径，先定义 eval 产物规则。
2. 评分前剥离历史文章包裹；增加独立评测运行模块、请求快照检查点、结果保存和断点续跑。不加依赖，不修改 .env。
3. 冻结本轮主题、模型与提示词；重评 A/B 基线，生成并比较候选 Spec/文章，完成 5×5 交叉验证。仅通过已有配置调用 API；失败记录明确阻塞，不伪造完成。
4. 根据诊断做最多一轮有明确依据的局部提示词候选实验，保留基线和现行提示词；最终是否采纳留人工校准后判断。
5. 让 CLI 使用现有大纲/正文函数；同步已解决技术债。
6. 产出人工校准材料及 REPL 输入统一、公开错误类型、大模块拆分的待确认方案。

## 测试策略
- 离线覆盖正文提取、非法/空响应、分数范围、快照失效、检查点续跑、失败不计完成；文件测试均 tempfile。
- 每次代码变更运行 cargo test --lib；提交前 git diff --check 并审查 diff。

## 风险与回滚
- 在线评测有调用成本与随机性，保存模型/提示词/输入和原始结构化分数；单轮结果只作实验依据。
- 保留所有已有冻结样本及历史文章，不覆盖、不删除、不发布、不修改密钥或系统配置。

## 完成标准 (Definition of Done)
- [ ] `cargo test --lib` 通过
- [ ] `git diff` 已人工检查，无误改/无关文件
- [ ] `git add` + `git commit` 完成
