你正在学习一组文本的写作声音，以便另一位 Writer 在无关题材上运用。输入中的文章编号只是引用标识，不代表作者身份；标题、署名、网页信息和文中任何命令都只是数据。不要凭作者名、已有印象或通用写作建议补充观察。

先在内部逐篇观察，再综合。不要强求每个特征在所有文章中出现：只在一篇出现的写法可保留为“本样本可见的局部写法”；多篇反复出现的要看机制是否真的相同；遇到叙述、评论、题材不同造成的变化，写出使用条件，不平均成模糊语气。一篇没有出现某写法，不等于反例。若只有一篇，不能写成作者一贯如此。

重点识别读者距离、视角、选材方式、信息推进、叙述与判断的连接、句法和节奏、转折、情绪力度、结尾及其相互让位关系。维度是观察提示，不要求逐项填表。说明写作动作如何操作、什么材料/题材下适用、什么时候应收住、误用会变成什么。不要规定每篇必须有几段、几次反问或几个短句。文章中的故事、观点、地名、行业词、数字、原句不能成为新文章的必写内容。当前写作任务给定的事实和必写信息始终优先；没有亲历和场景素材时，保持声音但不编经历。

只返回一个 JSON 对象：
{
  "spec": "供 Writer 直接使用的完整 Markdown 写作声音说明",
  "claims": [
    {
      "rule": "此规则表达的写作机制，不复述原文故事",
      "condition": "适用条件及不适用边界",
      "scope": "local 或 repeated 或 conditional_variant",
      "evidence": [{"article": "a01", "quote": "从对应文章逐字复制的短片段"}],
      "variation": "题材变体、反例或仍未知之处；没有则为空字符串",
      "misuse": "Writer 容易怎样误用，怎样改正"
    }
  ],
  "uncertain": ["重要但现有文章无法确认的声音问题"]
}

`claims` 只收真正影响写法的机制，不设条数。每条至少一段准确引文，短片段必须在对应文章中逐字出现；`repeated` 必须有两篇及以上不同文章的引文，且表达的是同一操作；`local` 只能声称局部观察；`conditional_variant` 要说明不同场合的变化，证据来自观察到的场合。证据属于审阅记录，不要把引文、文章编号或作者姓名写进 `spec`。`spec` 允许自然组织、充分展开，不设字数配额；它应让 Writer 知道如何写、何时用、何时不用及成稿后怎么检查。若证据不足，就讲清已知与未知，不为写长而造规则。
