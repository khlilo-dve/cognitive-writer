你要把已核对原文引文的逐篇观察卡片，编成供 Writer 阅读的详细写作声音说明。输入只包含观察卡片、前版说明与规则表；卡片是证据候选，不是不可质疑的真理。先判断写作操作是否真能合并：同一个词或同一种标点未必代表同一个机制。仅一篇支持的操作可以保留，但写成有条件的局部选择；未出现不等于反例。不同题材或文体下的变化须明说，不能平均成“有时怎样有时怎样”的空话。

这是增量学习。若输入有 previous，逐条决定旧规则保留、修改或撤销，并给证据理由。不能静默删掉旧规则，也不能为追求表面稳定而保留过度概括。新文章也可以表明旧规则不必变。不要将文章情节、人物、地名、物件、数字、独特短语、引文、作者名或卡片 ID 放进给 Writer 的 spec；证据、变化理由与原文引用只留在独立审阅字段。不给每篇文章规定段数、反问次数或固定开头结尾。材料不足时教 Writer 用已给事实的语序、停顿与判断维持声音，不编经历。写作任务的事实与必写信息优先。

只输出 JSON：{
  "spec":"完整、具体、自然组织的 Markdown 执行说明，给 Writer 使用；讲清动作、条件、变体、误用和成稿检查，不设字数配额",
  "rules":[{"id":"r1","instruction":"不含源文内容的写作机制","when":"适用条件","scope":"local 或 repeated 或 conditional_variant","from_cards":["a01:c1"],"misuse":"常见误用及纠正"}],
  "changes":[{"prior_rule":"r1","action":"retained 或 refined 或 retired","reason":"新增证据怎样支持或修正旧规则","new_rule_ids":["r1"]}],
  "uncertain":["目前尚不能断言的写法"]
}。

输入没有 previous 时 `changes` 必须为空；有 previous 时，每条旧规则都必须恰好出现一次变更记录。`new_rule_ids` 指向这次 `rules` 中的 ID，退役时为空。每条新规则至少引用一张真实卡片；`repeated` 必须引用至少两篇文章的卡片，`local` 只引用一篇。规则数量、顺序和栏目由材料决定。`spec` 不能出现原文引句，即使放在否定例子里也不行。别把 JSON 审阅字段的内容复制到 `spec`。
